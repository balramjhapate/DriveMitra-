# 17_Project_File_Structure.md

# Purpose

This document defines the complete project folder structure for the Car Rental Platform.

This is the **single source of truth** for the project architecture.

Every developer, AI coding agent, Antigravity, Cursor, Claude Code, Windsurf, Codex, or future contributor must follow this structure.

Never create random folders.

Never place files in incorrect locations.

Every file must have a single responsibility.

---

The project must be

- Modular
- Scalable

- SEO Friendly

# Naming Convention

Components

PascalCase

```

BookingForm.tsx

VehicleCard.tsx
```

Hooks

camelCase

```
useBooking.ts

useAnalytics.ts
```

Files

lowercase when appropriate

No spaces

No special characters

# Component Rules

- Accept props
- Be reusable
- Be responsive
- Support loading
- Support empty state
- Be accessible
- Be typed

# Code Quality

No duplicate components.

No duplicated business logic.

No inline styles.

No magic numbers.

No hardcoded colors.

No hardcoded spacing.

Everything configurable.

---

# Final Architecture Rule

Whenever a new feature is added,

first determine

- Folder
- Component
- Type
- Service
- Hook
- Route

Only then start implementation.

Never create files randomly.

This folder structure is the permanent architecture for the project.
